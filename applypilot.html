03 / product app / resume matching system

ApplyPilot

A job-application workflow app designed to help users organize roles, match postings to resume lanes, and understand why a specific resume version fits a specific opportunity.

Product Design UX Workflow Resume Matching Frontend UI Electron App Concept
role

Product direction, interface design, workflow logic, visual system, and iteration.

goal

Reduce job-application friction by helping users choose stronger resume versions for each job.

status

Ongoing prototype / local app concept with planned public launch exploration.

Problem

Applying to jobs often becomes messy: postings are saved in different places, resumes are duplicated, and it is not always clear which version of a resume best fits a role.

Product idea

ApplyPilot organizes job opportunities into a queue, evaluates them against different resume lanes, and gives the user a “why this resume” explanation before they build an application package.

Design direction

I wanted the interface to feel like a focused control panel: readable job cards, clear states, strong hierarchy, and transparent reasoning behind recommendations.

Resume lanes

ApplyPilot supports multiple resume directions, including UX/product design, frontend development, exhibit fabrication, fabrication engineering, and prototype technician paths.

Matching logic

The matching system weighs role signals differently, distinguishing design-tech work from fabrication-heavy roles while still allowing the user to override the recommendation.

Explanation layer

The “why this resume” panel explains which keywords, responsibilities, and role patterns influenced the recommendation.

Iteration

Later versions focused on clearer queue behavior, better search results, a stronger application package panel, updated cover letter support, and a more useful fabrication versus design-tech distinction.

What I learned

This project pushed me to think about product usefulness, workflow trust, information hierarchy, and how to present recommendations while still giving the user control.

Next steps

I would test ApplyPilot with real job seekers, simplify resume lane controls, improve job-import reliability, and explore whether the best launch path is a web app, local desktop app, or hybrid workflow.
